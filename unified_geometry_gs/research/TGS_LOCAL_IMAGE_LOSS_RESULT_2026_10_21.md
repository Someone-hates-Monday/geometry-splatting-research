# v24：批量局部图像损失 CUDA 模块

2026-10-21。完成独立损失模块的实现、编译与32组已有真实图像核验。本轮没有新的 TGS 原生前向、训练、backward 或模型编辑。所有图像和候选收益在 v23 已被观察，不作为新的质量评测。

## 实现结果

模块接收原始 float32 RGB、GT 字节、每个候选的像素区域及连续存储的候选 RGB 局部块，一次返回每个候选的三个 FP64 标量：全图归一化的 MSE、L1、SSIM 变化。原始图像值不裁剪、不量化；GT 按 double(byte)/255 转换。普通模式返回标量和诊断计数，SSIM 图仅在验证用调试模式返回。

独立 CUDA 源码 `tgs_local_image_loss_v24.cu` 使用半径5的两次可分离高斯滤波，统一计算基线、候选、GT 的均值、平方均值和交叉矩。SSIM 输出覆盖编辑区域外扩5像素，实际输入最多需要外扩10像素；全图边缘保持相同的零填充。空编辑区域直接产生零变化。

每个 block 固定256线程，使用固定树归约，再按候选固定顺序归约 block 部分和，没有浮点 atomic 求和。统计非有限输入／SSIM 值并要求为零。编译使用 `-O3 --fmad=false`、sm_120，未启用 fast math。当前 Torch 版本为 `2.12.0.dev20260314+cu128`，运行在 RTX 5090 Laptop GPU；具体二进制和源码哈希在 build receipt 中。

这延伸了 v23 的有限支持证明，完成了一个损失计算组件。接口目前消费已准备好的 RGB patch 和可信区域布局，尚未连接到渲染缓存的 patch 生成路径。CPU 布局、完整参考图像构造和 H2D 准备不计作已验证的端到端成本。

## 核验结果

8个软件夹具覆盖空／全图区域、角落、细边界、重复候选、未改变的 patch 和超出[0,1]的原始值。软件夹具通过，但不算真实数据结果。

真实核验使用 flowers／room 各两个已知视角的全部32个 hold/moved 候选。每个视角的8个候选批量运行，完整 RGB 从无损 patch 重建后先核验 v23 参考哈希。所有32例均通过以下检查：

- 局部与完整 GPU 计算，在保留区域内的 SSIM 图逐位相等；区域外 SSIM 差逐位为零。
- 普通与调试模式的三个标量逐位一致；普通模式没有 SSIM 图输出。
- GPU 图值相对独立 SciPy FP64 参考的最大绝对误差 **`1.9644e-12`**，低于预写门槛 `1e-10`。
- 三个局部损失变化量相对 v23 完整 CPU 参考的最大绝对误差 **`1.31595e-17`**；两种混合图像损失变化量的最大误差 **`2.62919e-18`**。
- 局部与完整 GPU 标量的最大差异 **`6.7763e-21`**。归约范围／分块不同会改变加法顺序，不能把这些浮点标量称为逐位完全一致。

标量的预写验证门槛为 `1e-13 + 1e-9*abs(reference)`；整个阶段未调整门槛。图值逐位门槛与上述数值容差分开检查，不能互相替代。容差及本批误差是实现核验证据，不是对任意未见输入的数学误差保证，也不是 FP32 训练算术的逐位复现。

64个“候选／视角 × 两种混合形式”比较中，GPU 与 CPU 的计算符号全部相同；其中4个参考值处于声明的容差范围内，不能作为稳定符号的证据。没有因为变化小而删除候选。

## 保留的研究限制

L1 图像形式取 `.8*Delta L1-.2*Delta SSIM`，L2 形式取 `.8*Delta MSE-.2*Delta SSIM`，不判断公开权重实际训练时采用的分支，也不包含 opacity、normal、distortion 等正则项。

此模块保留 v23 的目标不一致现象。按正／零／负三类比较，在32例中 PNG8 SSE 与 L1 混合形式有9例类别不同，与 L2 混合形式有7例不同；只看16个 moved 主分析例，分别为5例和4例。这里包含量化零与非零的差别，不能全称为符号反转，也不能据此估计总体发生率。

例如 flowers 父1387的 moved 候选在第二视角 SSE 改善，L1 混合形式却变差；room 父156483在第二视角 SSE 改善，两种混合形式均变差。新模块复现这些结果，没有把不同评分目标的差别误记为实现失败。

本轮没有做速度实验。不能把 FP64 局部损失实现正确等同于比完整渲染或原训练目标更快。局部垂直矩缓冲的布局推算约为44.9–170.2 MB／8候选批次，另有部分和及其他输入／调试存储；这不是总显存或实测峰值。当前还重复计算候选之间共享的基线／GT 矩，存在可优化空间，但增加共享缓存同样有建立和存储成本。

## 下一步实现与判别

只有在完整流程核验和成本对照之后，才适合评估冻结多视角上的收益聚合、独立场景和几何／图像质量。尚未得到新的质量增益、训练收益或学术创新性证据，不能将当前数值组件当作已成功的密度控制方法。
