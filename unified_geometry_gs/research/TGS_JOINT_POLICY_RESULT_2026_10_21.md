# v29：双视角覆盖、等预算联合细分仍未转移为留出收益

2026-10-21。完成两个已有场景各256个固定候选、五种规则各8次细分、4个新留出相机的前向诊断。**主规则在两个场景均改善校准分数、退化留出分数。** 这是对当前零步选择方案的负结果，不是最终训练、几何质量或创新方法成果。

## 设计和执行

沿用 v28 的两个训练集校准相机／场景，排除旧 v20 压力父项和全部 v28 候选。要求父项在两个校准相机的原生半径均为正、opacity>=.01、最大矩形面积不超过图像四分之一，再按最小校准投影面积分成四个等数量箱，每箱哈希选64项。flowers 合格集合177122项，room 47620项，全部 ID 与面积保留。

五个规则共享256项候选池、8次细分预算和冲突约束：混合损失变化、MSE变化、渲染扰动、最大最小投影面积、固定哈希。按各自分数贪心遍历，只有在两个校准视角的 SSIM 影响区域都与已选项分离才加入，直至8项。它不是最优独立集求解器。每种强制规则净增24个三角形；不编辑和负分 guard 另报。

单项使用 v22／v25／v26 的既有 CUDA 模块。原始 FP32 颜色每相机计算一次并保留，新增子项单独求物理质心方向 SH；删除所有已选父项后，按父 ID 升序追加各自四个 midpoint 子项。这是 v28 r1 的有限精度契约，不保证改变张量长度后重算全体 SH 的流水线等价。

四个新测试相机按冻结哈希选择，排除 v10／v12／v28 用过的相机；flowers 为 `_DSC9168`、`_DSC9144`，room 为 `DSCF4683`、`DSCF4971`。图像只在选择及校准联合门槛通过后获取。4组原始 JPEG 与公开 GT PNG 均解码逐位相同，无缩放、配准或裁剪。Windows 原生 TLS 有界 Range 共新增13701077 bytes，低于96MiB，无下载失败或整包回退。

共52次新原生前向：4个校准基线、4个子项库、20个校准联合参考、4个留出基线、20个留出联合参考。所有校准联合 RGB 与所选单项 patch 的拼接逐位相等，验证了 v27 充分条件在这20个8编辑集合／相机案例中的使用。新留出视角直接做完整联合渲染，未假设那里的单项可加。

独立 CPU 审计重放全部哈希采样、贪心选择和区域约束，从保存 patch 重建40个联合图像并验证全图哈希，重算 MSE／L1／SSIM。最大 CPU／GPU分数误差 **3.978301995e-18**，校准单项和相对 CPU 联合分数的最大差也为该值；未放宽1e-13+1e-9*abs(reference)门槛。

源审查在留出阶段执行前发现：原通用基线入口假定输出文件夹尚不存在，而身份审计已创建 GT 文件夹。未执行这个原留出入口；新增 `run_tgs_joint_policy_heldout_v29.py` 与哈希补充，仅处理现有文件夹，保留同一完整原生基线和联合参考定义。没有改动冻结的校准代码、相机、选择或分数。

## 主规则：校准改善，留出退化

使用变化量 `Delta[.8*L1+.2*(1-SSIM)]`，负值改善。flowers 的校准均值 **-5.236762179e-6**；两个留出视角分别 **+2.757530909e-7、+5.696724352e-6**，均值 **+2.986238722e-6**。留出平均 MSE增加 **3.819791815e-7**，L1增加 **1.812151787e-6**，SSIM减少 **7.682586460e-6**，平均 PSNR变化 **-0.0001455154 dB**。两张留出图分别改变144和4417个像素，因此不只是“选项在所有留出图都不可见”的零结果。

room 的校准均值 **-1.347877534e-6**；两个留出视角分别 **+8.585034202e-8、0**，均值 **+4.292517101e-8**。留出平均 MSE增加 **9.883646273e-10**，L1增加 **1.028674387e-8**，SSIM减少 **1.734788796e-7**，平均 PSNR变化 **-0.00000343436 dB**。一张图改变378个像素，另一张未改变。guard 在两个场景都选中同一集合，未保护留出目标。

## 全部同预算对照

flowers 的留出混合变化均值：MSE规则 **+3.741358395e-6**，扰动规则 **-7.826513607e-8**，最大最小面积 **-1.445610133e-7**，哈希 **-7.079018047e-10**。主规则仅比 MSE规则低，差于另外三种和不编辑；不能据校准排序宣称优越。

room 对应为：MSE规则 **-2.284644900e-8**，扰动规则 **-1.149472062e-9**，最大最小面积 **+6.481174667e-8**，哈希 **-1.480487257e-9**。主规则比面积规则低，差于其他三种和不编辑。部分对照的混合目标和 PSNR方向不同，例如 room 面积规则 PSNR均值提高约3.84e-5 dB但混合目标退化；所有单项指标及两个视角分别保存在 `analysis.json`。

这些是两个既有 checkpoint 的描述结果，不是总体显著性检验。v28 到 v29 同时改变了覆盖条件、候选种子／规模和编辑预算，不能把两轮差异单独归因于其中一项。当前证据也不能断言所有零步策略失败，或断言新增容量经过适应后必然有用。

## 固定预算下平均 opacity 项可以重新分解

v27 指出实际单编辑正则变化之和通常不等于联合变化。本轮补充：固定 k 时，可定义正确预算下的候选权重

`r_i^(k)=3*lambda*(o_i-mu)/(N+3k)`，

其和恰为联合平均 opacity 正则变化。若图像支持满足分离条件，图像项加上这一正则项可按固定 k 的权重相加；这不涵盖变预算选择、其他损失项或贪心最优性。

本轮通过 SymPy 核验一般公式，并从原 GPU 有效 binary32 opacity 的精确有理数值重算总和，对真实选中集合验证恒等式，没有用 CPU sigmoid 近似替代原输入。flowers／room 主规则的无 lambda 联合平均项变化系数分别为 **+4.214454335e-6、+6.928703590e-8**。因此，对这两个既定集合，本轮已计算的正向留出图像损失变化加上任意非负 lambda 的这一平均正则项仍不改善；这不是完整训练目标的结论，也不排除换一种规则选出的集合。

另测得 GPU FP32 `abs(opacity).mean()` 变化分别为 **4.187226295e-6、5.960464478e-8**。相对精确输入值公式的差分别约 **-2.72e-8、-9.68e-9**；而真实单项和与联合公式的差仅约 **-9.43e-11、-6.93e-13**。所以不能把实数公式中的微小耦合直接当作 FP32 训练可观测的同量级效应。历史 lambda 与其他训练配置未知，未做正则感知的重选，也未测完整训练收益。

## 后续外观适应需要方向可辨识性约束

补充证明采用当前每基元每相机一个质心方向的 SH 定义。三阶 SH 每通道16个系数，两个校准相机的方向设计矩阵秩最多2，故每个独立基元至少14维系数变化可保持所有校准颜色不变。更多同视角像素不会增加该基元的方向样本。这是标准线性代数补充，不是新的普遍定理；不等于实际图像 Jacobian 恰好有秩2，也不照搬到多质心共享系数的组。

CPU在真实选中8个父项及其32个子项／场景上评估方向矩阵；80个基元实例的双视角矩阵数值秩均为2，方向零空间维数14。新视角 SH 基向量在该零空间上的归一化投影长度中位数分别约0.734／0.912。它们不是误差率、不是拟合结果，也不能证明被遮挡基元实际改变图像。该计算用 float64 元数据方向，不冒充原生 FP32 逐位不变性；未使用 GT 或更新任何系数。

## 研究决策和后续边界

主规则当前没有转移收益，继续仅增加候选、编辑数或重新挑测试视角缺乏本轮支持。更有区分力的问题是：在原模型得到同预算适应的前提下，细分后的表示是否仍有额外收益。先准备原生颜色响应系数的固定扰动验证，再考虑少量 DC 外观适应；不直接在两视角上放开独立三阶 SH。

原始论文补查扩大了既有方法边界：[CF-Splat III-F](https://arxiv.org/html/2610.22108v1#S3.SS6) 已包含外观估计前的三角加密，不能只把它描述为“固定网格 SH 拟合”。完整访问边界及对 v26 比较范围的补充见 `TGS_RESEARCH_POSITION_UPDATE_V29.md`。细分、外观重拟合和方向正则各自已有先例，组合本身不能证明新颖性。

后续具体工作包见 `TGS_BOUNDED_APPEARANCE_NEXT_PLAN_V29.md`：先在现有数学／小规模 CUDA 诊断授权内准备颜色响应与有限扰动的完整参考核验；实际最多100步局部 DC 拟合仍须先有可执行协议，再由用户扩展当前“不含训练”的范围。该提案尚未执行，没有训练或模型接受。
