# v26：为完整与局部评分同时增加共享矩缓存

2026-10-21。完成共享基线／GT 矩缓存实现、32组已有真实图像核验和四端点同任务计时。没有训练、backward、接受的模型修改或新的独立质量数据。

## 结论

完整评分与局部评分现在都使用同一份共享矩缓存，消除了 v25 中反复计算基线／GT 矩的主要对照弱点。32例中，共享与未共享版本的分数及调试 SSIM 图逐位一致，CPU 参考门槛保持不变。

在这轮相同 FP64 评分任务中，缓存已建立时，批量评估8个候选分别需 **5.7443、2.9017、5.4172、2.9074 ms**；相对本轮完整场景＋共享缓存评分，配对中位加速比为 **6.2043、11.9602、12.4483、21.4741**。四视角依次为 flowers fresh、flowers old test、room fresh、room old test。不是与原生 FP32 训练的比较，也不是整体训练速度或最终模型质量结果。

新增共享缓存约 **74.9 MB／flowers视角、116.4 MB／room视角**。缓存建立和失效成本不能忽略；只有提供原图而没有任何缓存时，双方都正确计入损失缓存建立成本的条件比值约 **1.78–2.55倍**，明显低于热查询比值。上述冷条件是算术估计，不是进程／模型冷启动实测。

## 实现和数学条件

`tgs_shared_image_loss_v26.cu` 对每个 RGB 像素缓存三项 FP64 值：GT 局部均值、GT 局部方差、基线 SSIM。建立时暂存五个基线／GT 矩字段；每个候选只滤波 X、X²、X×GT 三个字段，替代 v24 的八字段重复滤波。高斯权重、半径5、零填充、原始未裁剪 RGB、GT字节／255、FP64 运算次序和固定树归约规则不变，使用 `--fmad=false`，不启用 fast math。

缓存只在基线 RGB、GT、相机／分辨率和权重不变时有效。调用者必须在这些条件变化时重建；当前研究接口没有自动跨训练更新维护缓存的机制。原始模型更新后不能把它当作免费、始终有效的状态。

按数组形状，候选垂直矩临时缓冲从八字段减为三字段，即原来的3/8。四批局部缓冲分别为63,806,688／16,836,480／51,790,752／30,756,096字节；这些是已知布局的缓冲大小，不是总显存。新增缓存分别为74,877,696或116,363,952字节，必须另计。

## 正确性核验

8个软件夹具保留空／全图区域、边界、重复／不变 patch、超出[0,1]的原始值。全部通过，但不计作真实质量证据。

真实阶段复用全部32个既有候选／视图组合。每视角只建立一次共享缓存；局部调试、普通模式和完整区域调试三个调用分别与原 v24 GPU 调用逐位比较分数及 SSIM 图，全部通过。共4次缓存建立、12次共享评分及12次未共享参考评分，不需要新的 TGS 原生场景前向。

局部／完整 SSIM 图值逐位一致，受影响输出区域之外差为零，普通／调试标量逐位一致。相对独立 CPU 参考，损失变化量最大误差仍为 **1.31595e-17**，图值最大误差仍为 **1.96443e-12**，符合既定门槛。不同归约范围下局部与完整最终标量可有浮点舍入差；未把浮点归约称为整数精确。

CPU 回执审计另行检查全部案例身份、已封存 v24 分数的逐位相等、缓存字节数及3/8临时字段比例；没有重复 GPU 图值实验。全部候选保留，没有把已观察过的数据称为独立泛化集。

## 计时设计

A 为完整场景控制前向＋共享缓存的完整图像损失；B 为逐候选4子基元前向＋缓存完整图像查询＋共享完整损失；C 为顺序4子基元前向＋动态局部块＋共享局部损失；D 为32子基元一次前向＋批量动态局部块＋共享局部损失。A/B/C/D 都复用相同的基线／GT 矩缓存并输出8×3个损失变化量。

预备模型、GT、候选参数／颜色、固定完整区域布局；C/D 包含子基元前向、几何解析、区域规划、GPU→CPU 同步、CPU 布局、布局传回 GPU、局部 RGB 输出、候选矩、归约及临时分配。原生控制 API 的不相关分配及子基元库的无用混合渲染仍计入。该控制保留了 API 分配，尚不等于理论最小的专用完整渲染接口。

四个已知视角，每视角2个四端点预热块、8个预写平衡 Williams 测量块；共32块、128个端点。第一轮预热核验四方法全部分数和诊断标志。控制前向预算 `4*[1+(2+8)*(3*8+1)]=1004`，实际计数一致并正常退出。每个建立回执和测量块立即写出，无删点或追加计时。与 v25 为不同运行和新预写顺序，不能用两轮耗时直接构造配对因果加速比。

## 本轮同任务结果

下列耗时为各方法自己的中位数，比值为同块比值中位数。

flowers fresh：A **35.5185 ms**，B **32.2651 ms**，C **16.2997 ms**，D **5.7443 ms**；A/D **6.2043**，B/C **2.0099**，C/D **2.8447**，B/D **5.6871**。

flowers old test：A **34.7698 ms**，B **28.2947 ms**，C **10.9712 ms**，D **2.9017 ms**；A/D **11.9602**，B/C **2.6252**，C/D **3.8382**，B/D **9.8378**。

room fresh：A **67.3385 ms**，B **42.0557 ms**，C **13.7039 ms**，D **5.4172 ms**；A/D **12.4483**，B/C **3.0689**，C/D **2.5677**，B/D **7.8347**。

room old test：A **62.3029 ms**，B **37.2802 ms**，C **10.6194 ms**，D **2.9074 ms**；A/D **21.4741**，B/C **3.5141**，C/D **3.5159**，B/D **12.7919**。

32块中没有 D 比 A 慢的块，全部异常偏高耗时点保留。B/C 仍同时改变 RGB 输出与损失区域，不能只归因给某一个 kernel。C/D 反映本批条件下批处理的组合收益，不是对所有候选大小／场景的保证。

D 的额外峰值分配中位数依次为 **145,461,248／90,595,328／171,829,248／147,271,168字节**；C 为 **100,349,952／100,338,688／156,948,480／156,939,776字节**。因此两个 fresh 视角批量分配较大，两个 old test 视角较小，不能套用 v25 的一概判断。所有增量均排除常驻模型、预建候选、几何和新增损失缓存；不能据此宣称总显存下降。

## 建立成本与缓存合同

分别记录原始控制渲染／缓存解析 R 与损失缓存建立 L：

flowers fresh：R **11.490821 ms**，L **6.321627 ms**，总计 **17.812448 ms**。

flowers old test：R **7.193551 ms**，L **6.134881 ms**，总计 **13.328432 ms**。

room fresh：R **14.894681 ms**，L **9.975020 ms**，总计 **24.869701 ms**。

room old test：R **15.291560 ms**，L **10.617938 ms**，总计 **25.909498 ms**。

这些是同进程一次性观测，模型、颜色、GT、固定权重／完整布局已就绪，不含 CUDA／模型／数据冷启动。R 包含当前缓存／alpha解析，完整 RGB-only 基线可省去部分工作。

已有原图、没有缓存时，完整方法也必须建立共享损失缓存，所以条件比值是 **`(L+F)/(R+L+D)`**，依次 **1.7761／2.5203／2.5527／2.5305**；不能误用 `F/(R+L+D)`。若双方都需原始渲染，以共同建立合同计算 **`(R+L+F)/(R+L+D)`**，依次 **2.2639／2.9635／3.0445／3.0611**。仅有原图和损失缓存、没有几何缓存时，`F/(R+D)` 为2.0608／3.4442／3.3152／3.4234。这些均为建立观测加热端点中位数的算术估计，不冒充实测冷批次。

## 研究判断与下一步

本轮支持的是在更强、同精度完整评分参考下仍存在候选评分效率收益。代码还可优化，但继续只微调耗时不足以满足原始科研目标。下一阶段优先检验：多个拓扑编辑的相互作用，以及未用于选择的额外视角／独立场景上的收益。单候选分数不能未经核验就相加，也不能把即时损失改善等同于参数适应后的训练收益。

原始文献定位已更新在 `TGS_RESEARCH_POSITION_UPDATE_V26.md`，逐项链接原论文／作者页面并说明覆盖边界。局部缓存、有限 SSIM 邻域、共享矩和基本损失展开本身不构成新颖性证明。当前仍没有新的几何／图像质量提升、完整训练收益或独立泛化证据。

本轮起／终遥测 SM 读数为120／330 MHz，不能代表测量中每个端点的实际频率。前轮遥测异常原始记录保持不变；本轮未改／锁频，也未据遥测调整或重跑样本。墙钟和 CUDA 事件区间只是这台设备上的观测，后者包含主机提交间隙，不等于纯 kernel 忙碌时间。
