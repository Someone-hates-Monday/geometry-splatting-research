# v22：固定场景的批量反事实 PNG8 误差查询

2026-10-21。范围：数学核验和小规模固定输入 CUDA 诊断。没有训练、优化器、接受的模型修改或 GT 驱动的候选筛选。

## 当前结论

在两个已有公开 TGS 权重的指定相机上，16 个既定细分候选全部通过全局 RGB、alpha、贡献路径的逐位一致性核验。批量 CUDA 返回的 PNG8 SSE 差值与完整渲染后 GPU 归约、独立 CPU 整数计算完全相同。一次查询 8 个候选时，预备缓存条件下相对逐个完整渲染的配对中位加速比为 flowers **4.6868 倍**、room **10.2202 倍**。

这是固定候选误差评估工具的正确性与成本结果。尚未证明细分选择策略、重建质量、跨视角泛化、训练收益或论文创新性。两个场景、两个既有相机、同一批已探索候选，不能当作独立泛化评测。

## 数学与实现

对于固定原图 B、候选图 X 和已验证身份的 GT 字节 G，计算

`D = sum[(q(X)-G)^2 - (q(B)-G)^2]`。

q 使用两次独立的 FP32 RN 运算：先乘 255，再加 0.5，随后截断到合法 PNG8 字节。编辑基元原有和新生 tile 矩形并集之外，基元列表未变且 X=B，误差差值为零。局部查询必须保留原生列表顺序、稳定深度并列规则、window、alpha 截断和“当前项不纳入”的提前停止语义。

每个候选的四个子基元可拼为一个 4K 预处理库，条件是预处理只依赖自身参数和相机。每个候选只把自己的四个子基元与删除自身父基元后的旧列表合并。库的混合渲染图被丢弃，不能作为任何候选的图像。当前仍调用完整原生前向获取库的预处理字段，包含其多余分配和混合渲染耗时。

每个 256 像素 block 的三通道整数差值绝对值最多为 `256*3*65025 = 49,939,200`，在 int32 内；全图部分和绝对值由 `3*H*W*65025` 控制，在接口限制下远小于 int64 上限。因此整数原子加的顺序不影响结果。该论证只保证已量化误差归约的精确性，不是整个 FP32 光栅化程序的形式化证明。完整条件见 `TGS_BATCH_SCORE_CORRECTNESS_NOTE_V22.md`。

## 正确性证据

- 软件夹具：769 个量化阈值附近/边界输入，多个独立候选、相等深度、仅删除父项、空 ROI、257 层记录；全部通过。
- 真实输入：2 个原始基线、2 个 32 子基元库、16 个完整候选参考，共 20 次原生/控制前向。可见缓存字段、每 tile 合并列表、全图 RGB/alpha/路径全部一致，参考图哈希复现 v20。
- GT：原始 JPEG、发布 PNG、保存的解码数组逐字节一致；无缩放、裁剪或拟合。基线量化与独立 CPU PNG8 实现一致。
- 三种 SSE 差值逐整数相等。独立 CPU 审计从 v20 基线和无损 patch 重建完整候选，复核图像哈希、候选输入、GT 和分数。
- 分数共 3 个负、13 个正、0 个零；保留全部结果，没有接受任何编辑。负分仅说明该固定视图的该候选降低了这个量化 SSE。

固定顺序为四个父基元各自的 hold/moved 颜色候选：

flowers：`1553284, 1540410, -160029, -174081, 423, 261, 83138, 83058`。

room：`868448, 861661, 91, 122, -877, 66, 1281, 1297`。

## 四种同分数端点的计时

A 为完整场景控制前向加全图整数归约；B 为逐候选缓存图像查询加全图整数归约；C 为逐候选标量 ROI 查询；D 为批量标量 ROI 查询。都返回同样的 K 个 int64 分数。A 使用 v21 已移除不相关辅助算术的控制前向，避免把旧原生辅助输出的额外工作都算为新方法优势。API 分配仍保留，尚无专用最小化完整场景打分后端。

候选参数、颜色、GT、基线 PNG、静态库切片在端点外准备。端点包含新生子基元前向、ROI 规划/前缀和、同步和归约；不免费复用子基元预处理缓存或 ROI 计划。模型与候选准备、GT 传输及常驻缓存内存不包含在 warm 端点时间内。K=1/2/4/8 为同一候选序列的嵌套前缀，覆盖区域构成随 K 改变，不能据此分离纯批大小效应。

每个场景/大小先运行 2 个四端点预热块，再运行预写 Williams 顺序的 8 个块。总计 64 块、256 个被计时端点，位置和块内相邻顺序均衡；无删样或追加计时。下列耗时为各方法的中位数，加速比为同块比值的中位数，两者不能直接互相相除复算。

K=8，flowers：A **16.2803 ms**，B **12.8294 ms**，C **13.1857 ms**，D **3.4523 ms**。A/D **4.6868**，B/C **0.9861**，C/D **3.6896**，B/D **3.6814**。

K=8，room：A **36.3808 ms**，B **11.5972 ms**，C **11.1319 ms**，D **3.5504 ms**。A/D **10.2202**，B/C **1.0184**，C/D **3.0962**，B/D **3.2716**。

主结果的 16 个 K=8 块中没有 D 比 A 慢的块；小前缀 flowers K=1 存在一个较慢块，全部原样保留。B/C 接近 1，当前没有证据表明仅去掉完整输出图像就带来明显加速；C/D 显示批处理在这组端点中有显著成本收益。这里的“批处理”包含共享子基元前向与减少调度/同步，不能再归因给某一个 kernel。

K=8 的额外峰值分配中位数 A/D 分别为 flowers 320,090,112 / 71,348,224 字节、room 657,520,640 / 111,796,224 字节。此项是端点相对当前常驻量的分配增量，不是总显存；大模型、预先构建的候选和共享缓存仍驻留。

图 `experiments/tgs_batch_score_v22/batch_score_cost.png` 显示四种端点、全部大小和全部原始块，不给出场景总体置信区间。

## 缓存成本和收尾错误

原计时程序实际完成所有八个单元及模型输入哈希核验后，在最后的调用数断言失败，进程退出码为 **1**。预写数量 954 有算术错误；四端点设计实际为

`2 * [1 + (2+8) * sum(3K+1, K in {1,2,4,8})] = 982`。

实际比预写数量多 28 次。原脚本、协议、错误栈和八个原始单元保留不改。`recovery_plan.json` 和 `results_recovered.json` 记录 CPU 恢复及核验，未重新计时。原进程的缓存建立时间与最终遥测没有写出，不能恢复或补猜；不能称其成功退出。

之后另行冻结并执行了一次性、独立进程的 2 次前向附录，观测缓存/基线 PNG 建立时间 S：flowers **14.4274 ms**、room **14.6265 ms**；保留缓存与 PNG（不含 GT）分别 **332,260,755** 和 **685,058,193** 字节。这不是原计时进程的 S，也不是冷启动端点复测。v22 的原生/控制前向合计为 20（正确性）+982（原计时）+2（附录）=**1004**。

仅作条件算术估计，F/D 取 K=8 各自中位端点时间：若已有基线 PNG 但无几何缓存，完整方法与局部方法成本比为 `F/(S+D)`，flowers **0.9105**、room **2.0015**；若两者均需要原始基线渲染，采用共同 S 时为 `(S+F)/(S+D)`，分别 **1.7175**、**2.8062**。flowers 的第一种条件下没有优势。跨进程 S、热端点和准备工作排除使这些只能用于估算，不能冒充实测冷批次收益。

## 后续研究判断

优先保留“精确、可批量的候选评分工具”这条效率线索。下一阶段应先冻结跨视角和独立场景的候选集合，检验已知视图上的分数排序能否预测其他视图的收益；先排除遮挡、观察次数和颜色重估造成的排序翻转，再决定是否值得设计密度控制策略。

当前 PNG8 SSE 不是原生 float L1+DSSIM 训练目标，不能直接把分数当作训练策略。需要检验目标一致性、额外内存、缓存失效重建和完整候选构造成本，并补充相同工作范围的专用完整打分后端。尚须进一步比对已有局部评估/密度控制工作，才能判断学术贡献。这里仅记录下一阶段，不启动新数据下载、策略执行或训练。
