# v23：跨视角收益与评分目标核验

2026-10-21。固定公开权重，完成20次新 CUDA 前向和已有图像的 CPU 数学核验；没有训练、反向、接受的编辑、新数据下载或独立场景验证。v22 的封存结果保持不变。

## 当前判断

批量评分工具的精确性在第二个已知视角得到复核，但单视角 PNG8 SSE 不能直接充当密度控制的充分依据。有限实例显示两类问题：同一编辑的收益符号随视角变化，以及同一图像上 SSE 与 L1/L2+DSSIM 形式的损失出现符号不一致。排序相关高也不足以保证收益符号正确。

数学和实现方面有一个可继续利用的结果：对于已知编辑区域，点损失只需区域内重算；11×11 有限窗口 SSIM 只需重算区域外扩5像素的输出，并保留区域外扩10像素的输入。32个实际候选／视图组合上，该局部计算的 SSIM 图值与完整计算逐位相等。这允许下一阶段实现与图像目标一致的批量局部评分，不必把 PNG8 SSE 当作所有训练目标的替代品。

## 输入、设计和证据范围

沿用 v20 每场景四个固定父基元及各自 hold/moved 两种颜色模式。原视角为 flowers `_DSC9136`、room `DSCF4755`；第二视角为此前已验证 GT 的 flowers `_DSC9128`、room `DSCF4915`。模型、候选、相机、GT、参考图、脚本和二进制在新输出前写入 `plan.json` 并冻结哈希。

主分析使用 moved：四个子基元继承相同父 SH 系数，在各相机重新求值，代表相同的模型参数编辑。hold 仅固定为该相机的父颜色，是属性归因诊断，不能假定为统一的跨相机 SH 模型。所有16个新视角候选均保留，含无像素变化和量化零变化；旧视图和原候选已有探索历史，不能当作全新独立测试集。

第二视角执行2个原始基线、2个32子基元预处理库、16个完整候选参考，恰为20次。每例的可见缓存字段、完整 tile 列表、全图 RGB/alpha/贡献路径均与参考一致；批量标量分数、完整图像 GPU 归约和独立 CPU 整数差值完全相等。原始基线复现 v14 的预计算颜色图像。GT JPEG、发布 PNG 和保存数组逐字节一致。全部脚本正常退出，模型输入哈希不变。

## 同一编辑的跨视角 SSE 变化

以下均为 moved；负数为 PNG8 SSE 降低，零单独保留。

flowers，父 ID 顺序 `1436, 1387, 2773, 110`：

- 原视角：`1540410, -174081, 261, 83058`。
- 第二视角：`0, -849, -87, 503775`。

四例中2例符号相同，1例正转负，1例正转零；秩相关 rho=0.8，六对排序关系5同向、1反向。父1436在第二视角无受影响区域，图像逐位未变。

room，父 ID 顺序 `171415, 156483, 58, 2628`：

- 原视角：`861661, 122, 66, 1297`。
- 第二视角：`0, -1399, -21987, -721`。

四例中0例 SSE 符号相同，3例正转负，1例正转零；但 rho=1，六对相对次序全部同向。这个有限反例说明“排序一致”与“收益符号可迁移”是不同要求。父171415在第二视角仍有93个 RGB 像素发生浮点变化，PNG8 SSE 差为零，不能把量化零解释为没有渲染变化。

这些是八个特定父基元在两个依赖视角上的描述，不估计总体失败率，也不按像素计算显著性。

## SSE 与图像损失形式不一致

源码复核显示，归档 TGS 的图像项为 `.8*pixel_loss + .2*(1-SSIM)` 的默认形式；`large_scene and outdoor` 条件下 pixel_loss 为 L2，其余为 L1。公开权重保存的 cfg 不足以证明历史训练分支和所有超参数。此前把训练项一概称为 L1+DSSIM 的表述过宽，应以这里的条件说明为准。

本轮对原始、未裁剪 RGB 重算 float64 的 MSE、L1、固定 SSIM 和两种默认权重混合形式。它们反映图像目标形式，既不是 GPU FP32 训练算术的逐位复现，也不包含 opacity、normal、distortion 等其他正则项；`.2*(1-SSIM)` 沿用源码定义，没有另除以2。

例如 flowers 父1387的 moved 候选在第二视角 PNG8 SSE 降低849，原始 MSE 变化约 `-6.7233e-9`，但 L1 变化约 `+1.4754e-6`，`.8*L1+.2*(1-SSIM)` 变化约 **`+1.1735e-6`**。同一编辑的 SSE 改善不能推出该 L1 混合图像项改善。

room 父156483在第二视角 SSE 降低1399，但 L1、L2 两种混合形式分别约增加 **`3.2485e-8`** 和 **`5.8092e-8`**。原视角 room 父58的 moved 候选则 SSE 增加66、两种混合形式均降低。所有量级和全部 hold 结果保存在 `analysis.json`；极小变化不能冒充显著模型质量收益。

图 `experiments/tgs_view_transfer_v23/view_and_loss_alignment.png` 显示全部16个主分析观测；灰线仅连接同一编辑的两个视图。纵轴为明确标注线性区的有符号对数轴，所有面板使用相同范围，无删除零值或选择性放大图像。

## 有限邻域损失补充证明与真实图像核验

新附录在上述结果之后形成，明确标为数据启发的数学核验，不冒充原先预注册。

设 B 与 X 仅在已知区域 R 不同。任何逐像素损失差在 R 外为零。SSIM 的每个输出仅依赖其11×11邻域，因此在 R 外扩5像素所得 A 以外，SSIM 图不变。要重算 A 内所有输出，需提供 A 再外扩5像素的输入，即最多 R 外扩10像素。裁剪到原图边缘时使用相同的零边界条件，最后仍除以全图 `3HW`。

在全部32个实际候选／视图组合上，CPU 校验完整图像哈希和 R 外像素一致；A 外 SSIM 差逐位为零；裁剪计算的 A 内 SSIM 图值与全图逐位一致。局部／全图的最终 MSE、L1、SSIM 归约最大绝对残差为 **`2.7105e-20`**，均在事先写明、按各例项数与绝对和计算的保守 FP64 求和误差界内。PNG8 SSE 局部归约仍逐整数相等。

条件、公式和误差界见 `TGS_IMAGE_LOSS_LOCALITY_NOTE_V23.md`；代码与逐例数值见 `verify_tgs_image_loss_locality_v23.py` 和 `loss_locality_results.json`。这不是整个 CUDA 程序的形式化证明，不保证 GPU FP32 卷积逐位一致，不覆盖全局正则项或 backward，也不是速度或质量实验。有限依赖关系本身是标准数学性质，不宣称新定理。

## 下一步

优先实现有限邻域 L1/L2+DSSIM 批量评分，以完整图像目标为参考核验精度与成本。随后在冻结的多视角候选集合中检查绝对收益和排序，并计入缓存失效、候选构造、基线预处理、内存及完整评分基线。需要独立场景和最终几何／图像对照，才能判断是否形成有价值的方法贡献。

本轮不接受 GT 驱动的编辑，不依据这些测试视角调整模型，不训练、不搜索阈值或 lambda。现有证据支持继续改造评分工具，不支持直接宣布新密度策略有效或达到论文目标。
