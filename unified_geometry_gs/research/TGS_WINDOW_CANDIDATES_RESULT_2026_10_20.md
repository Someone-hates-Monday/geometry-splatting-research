# v9：单遍粗排除通过精度与算子成本筛选；标准幂函数候选失败

本轮范围：数学核验和隔离环境固定输入 CUDA 诊断；没有优化器、完整训练或 GT 评估。
总体科研目标仍未完成。此次有可复现的正向工程结果，但学术新颖性和真实质量收益尚未成立。

## 实现与数学结论

- `coarse` 从封存 v5 隔离复制。新增一个保守的 FP32 平面外部判断；无法证明在外部的窗口全部执行原来的 native64 边、归一化、幂函数和 alpha 运算。删去此前完整的预检遍历，最终渲染只遍历一次；反向共用窗口判断。原投影、裁剪、法向、Jacobian、SH、合成顺序不变。
- 缓存从 10 改为 14 个 float/三角形，相比 v8 的 48 个 float 明显缩小。保留原有 double 系数及其他缓冲。真实 geometry buffer 从 259,526,464 增至 272,071,360 B，增加 12,544,896 B；不能声称相对 native64 节省显存。
- `standard` 只将 v8 补偿窗口的显式快速幂函数改为已诊断的低层 `__nv_powf`；其余 48-float 缓存、双遍历和经验 power 预算均保留。
- 条件外部证书及运算/范围假设见 `TGS_COARSE_REJECTION_NOTE_V9.md`。对缓存 binary64 平面 c 与 h=RN32(c)，E=D+2^-22 M+2^-51 M64 包含系数转换及两种指定点积运算的误差。max(d32)>E 可推出某个 native64 边值>0。证书不覆盖原始投影、几何或 tile 构造；这不是新的通用浮点定理。

## 精度证据

固定计划先于结果冻结，全部沿用 127 个旧案例；每个版本核对 70,680,828 个像素。
六版本共 3858 次选定 VJP；三 lean 版本共 7776 条有限差分记录，每版 2592 条，复用方向不能当作独立科学样本。

- `coarse`：所有旧案例和七张真实整图的 RGB、七辅助通道、maxblend、路径及半径均逐位等于只读旧 native64 oracle。所有 replay flags 和 preflight 计数为零。两种固定上游的六组真实 VJP 均通过预先更严格的相对 1e-5 门槛，最大相对差 1.060913e-6。
- `coarse` 与 oracle 的全部 2592 对有限差分正负端点样本也逐位相同。有限差分支持稳定；数值归一误差中位约 7.011e-5、90 分位 0.001514、99 分位 0.032592、最大 1.368636。不能将其描述为所有 FD 都在 1e-3 内。
- `standard`：旧案例通过，七相机中六张通过。在 `_DSC9213` 仍有六个新加权深度失败像素，最大 3.4332275390625e-5，超过冻结的 3e-5。旧 v8 的 14 个失败点此次全部在门槛内，其中四点深度逐位相同；局部回归通过不代表整图通过。六个新失败点及各通道差异均记录在 `failure_census.json`，阈值未改。没有计时该候选。
- counter/lean 的前向、缓存和路径逐位一致，选定 VJP 通过。lean 前向 SASS 中计数 ADD 数为零；单遍结论还依赖源码及运行时零 preflight，不能仅靠死模板未出现在 SASS 的假设。
- 缓存 Fraction 审计：每候选全部小案例 747 条边，以及预先选定真实子集 11,421 条边；全部可见真实三角形的 footprint/domain 均核验。独立精度审计复查 777 个封存文件哈希和 452 个原始源文件哈希。

真实输入均为同一个公开 stump7000 检查点，784,056 个三角形、SH3、1245×825。相机顺序为
9258、9322、9269、9221、9213、9326、9293；最后一个是在输出前按 SHA 规则选取的新 test 相机，前六个已参与过研究。
新增相机不是新增场景或训练种子；没有使用未核实映射的 GT 图像。

独立审计最终决定：`coarse=true`、`standard=false`、两候选总门槛 `false`；仅允许 `coarse` 进入成本测量。

## 固定输入成本：正向结果和限制同时保留

事先冻结七相机、三版本（oracle/coarse/历史 piecewise）、全部六排列各三次，126 个配对 block、378 次正式前向＋反向调用，另有 63 次固定预热。
所有计时点保留，未因离群、频率或正负结果重跑。模型和上游梯度输入的前后哈希一致。
主估计量为同一 block 内 coarse/oracle 墙钟前后向比值的中位数，按相机分别汇报；不是边际中位数之比。

七相机的主比值及单次会话描述性 95% 配对 bootstrap 百分位范围分别为：

- 9258：0.749259，[0.743395, 0.763518]。
- 9322：0.740305，[0.708080, 0.796049]。
- 9269：0.741011，[0.714636, 0.817411]。
- 9221：0.735491，[0.683087, 0.779068]。
- 9213：0.734012，[0.679764, 0.808215]。
- 9326：0.737476，[0.694613, 0.770502]。
- 新相机 9293：0.741558，[0.697490, 0.775246]。

即本会话相对同数值语义 native64 参考的墙钟前后向耗时降低 25.1%–26.6%。七相机均通过事先规定的中位数<=0.90且描述性范围上端<1的工程筛选。
独立成本审计重建了全部平衡顺序，并单独复算了 20,000 次 paired-block bootstrap。

前向配对中位比约 0.730–0.745，反向约 0.736–0.751。诊断计数表明约 85.8%–87.6% 的已访问窗口不再进入 FP64 窗口求值；该工作量比例不能替代时间测量。
Torch 峰值 allocated 为 coarse 969.2–1018.6 MB、oracle 956.6–1006.0 MB，每相机增加 12 MiB（12,582,912 B）。reserved 与 driver 的使用量不等同于这些 allocated 数值，也不等同完整训练峰值。

历史 piecewise 仅作为不同数值实现的背景：coarse/piecewise 配对中位比仍为 4.94–5.37，oracle/piecewise 为 6.55–7.24。
因此本轮没有超过该历史实现，不能凭 native64 参考上的改善宣称整体 TGS 最优或与历史实现 GT 质量等价。

GPU 为 RTX 5090 Laptop、CUDA 12.8；本会话未锁频，观测 graphics clock 1530–2962 MHz、温度 47–61°C。
所列百分位是单设备单次会话的描述，block 可能有时间相关性，不是跨场景/训练种子的总体置信区间；不报告 p 值。
计时覆盖 native API 的分配、host sync、前向及反向，CUDA events 也含 launch gaps；不是纯 kernel 或完整训练吞吐。

原始数据、配对 CSV、顺序/时间趋势和位置分布都在 `experiments/tgs_window_candidates_v9/cost/`。
最终排版 `paired_cost_v3.png/.pdf` 左图显示全部原始配对点，右图同时显示较慢的历史背景比较；`figure_data_v3.csv` 保留图源数据。前两次排版存在顶部裁切，也保留其文件；最终修正了布局矩形的高度定义，未重跑计时，三版图源 CSV 哈希相同。

## 下一步优先级

1. 将该版本作为“保留指定 native64 输出的精度/效率基线”保留；首先查真实跨场景固定输入，而非继续只在 stump 的旧相机上修补小像素。
2. 解释仍落后 piecewise 约五倍的成本来源：缓存构造、精确内部窗口及反向等分别是否主导。下一轮需要先冻结可区分这些原因的算子诊断；不从窗口计数直接推断瓶颈。
3. 近似内部 alpha 若要恢复，必须补足对完整深度/透明度/合成舍入轨迹的约束。只提高幂函数精度已被整图证据否证为充分方案；不得再以旧14点局部回放代替全图准入。
4. 科研贡献仍需与成熟保守谓词/精确回退等先验区分，并证明对实际几何、图像或可用效率有价值。GT 映射、跨场景和最终训练质量仍未完成；本轮不扩展到完整训练。

失败 v5/v8 和本轮 standard 均保留。原始仓库源归档、既有封存文件和打开的 `median_depth_note.tex` 未修改。
