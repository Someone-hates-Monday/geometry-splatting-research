# v25：局部 RGB 与图像损失评分接线及完整候选端点成本

2026-10-21。固定权重、固定候选、四个已知视角。实现了“渲染缓存 → 连续 RGB 局部块 → FP64 图像损失”的完整候选评分路径，并完成正确性和同任务成本对照。没有训练、backward、接受的编辑或独立质量数据。

## 结果与主要限制

32个候选／视图组合的局部 RGB 与既有完整参考逐位一致，重建完整图像的哈希完全复现；接入后的 MSE、L1、SSIM 变化量逐位复现 v24。批量路径不先克隆每个候选的完整图像，再做损失裁剪。

在当前 FP64 评分实现下，一次评估8个候选，四个视角相对逐候选完整渲染＋同一 FP64 损失的配对中位加速比为 **6.92、15.21、13.87、23.27倍**。所有32个测量块均保留，未出现批量路径比该完整参考更慢的块。

这是当前候选评分原型的成本结果。完整参考和局部路径都仍重复计算可共享的基线／GT 局部矩；必须先强化完整评分基线和共享缓存实现，才能判断最终效率贡献。这里没有与原生 FP32 训练速度比较，也没有模型质量或论文创新性结论。频率遥测另有异常读数，不能据此声称锁频或稳定频率条件。

## 实现与正确性

`tgs_packed_patch_v25.cu` 延续 v22 的原生 window、alpha 截断、skip-current 提前停止、删除父项以及稳定深度合并规则。每个候选只纳入自己的四个子基元，没有固定贡献层数截断。输出为按候选排列的 CHW 局部块；矩形内不含父／子项的 tile 必须复制基线 RGB。区域可能很大，极端情况下也可能覆盖完整图像，不能保证每个候选都小。

软件夹具覆盖稳定并列、独立候选、父项删除、空区域、257个保留原始层，以及受影响矩形中间一个未编辑但非零颜色的 tile；全部通过。软件夹具不算真实场景证据。

真实验证沿用 flowers／room 各两个已知相机、四个固定父基元及 hold/moved 各一种颜色模式。每视角一个原始控制前向、一个32子基元库前向，四视角共 **8次控制前向**，不重新渲染32个完整候选参考。库的混合图被丢弃；原始基线、子基元参数／颜色及区域边界复现既有记录。

直接输出的32个 RGB 局部块与 v20/v23 无损参考逐位一致；CPU 独立重建完整图像并核验 v23 哈希。v24 损失二进制保持不变，接线后所有32个三维 FP64 分数向量与 v24 逐位相等。原始模型输入哈希在每视角后不变，没有把候选写入场景。

颜色模式的范围保持不变：moved 为同一继承 SH 参数在各相机重新求值；hold 是相机相关的父颜色归因诊断，不能当作统一的跨视角 SH 模型。四个相机和全部候选均有既往探索历史。

## 四种同任务端点

A：每候选完整场景控制前向，加完整区域 FP64 损失。B：每候选4子基元控制前向、v19 缓存完整图像查询，再加完整区域 FP64 损失。C：每候选4子基元控制前向、动态区域规划、连续局部渲染和局部 FP64 损失。D：一次32子基元控制前向，再批量执行与 C 相同的动态评分路径。

全部端点返回8×3的原始 MSE、L1、SSIM 变化量。预先提供模型、GT／基线 RGB、候选状态和颜色；完整区域损失布局是固定的，可在端点外准备。C／D 则计入动态子基元前向、几何解析、区域规划、GPU→CPU 矩形同步、CPU 布局、布局／权重传回 GPU、局部块写出、FP64 矩与归约，以及全部临时分配。当前 CPU 往返是原型的真实成本，没有免费复用子基元或区域缓存。原生 API 的不相关分配及库的无用混合渲染也计入。

每视角2个四端点预热块、8个预写 Williams 测量块；每个方法在各位置及块内有序相邻组合均衡。第一轮预热验证全部方法的分数在 v24 预写容差内并且诊断标志为零。没有删异常点、追加重复或按性能停止。总计 **32个测量块、128个被计时端点**。

调用预算在运行前从实际四端点设计计算：`4*[1+(2+8)*(3*8+1)]=1004`。计时阶段实际计数一致并正常退出。每视角建立缓存后立即写出 S，逐块写出原始记录，避免把建立时间留到最终汇总才落盘。本阶段共8次正确性前向＋1004次计时控制前向＝**1012次控制前向**；两个预算分别冻结，无训练迭代。

## 同进程缓存建立成本

四视角原始控制前向／缓存解析 S 分别为 **11.3173、6.3969、15.8193、14.7695 ms**；不含模型、颜色、GT 加载或进程／CUDA 冷启动。不含 GT 的保留缓存／原始输出／颜色分别约 **329.1、324.7、680.2、664.5 MB**，另有 GT 与模型／候选常驻内存。

以同进程一次性 S 和各方法中位热端点作条件算术估计：若已给基线 RGB、但无几何缓存，`F/(S+D)` 分别为 **2.8093、5.3432、4.1516、4.7927**；若双方都需原始渲染，采用共同 S 的 `(S+F)/(S+D)` 分别为 **3.4033、5.9916、4.8489、5.5863**。这是条件估算，不是实测冷批次。共同 S 包括缓存／alpha 解析，完整参考若只需 RGB 可以省去部分工作，不能把该共同建立合同视为最优完整基线。

## 遥测与证据限制

初始遥测记录 SM 为8040 MHz，超过后续 Windows 原生查询报告的最大3090 MHz；WSL 后续查询也报告了最大3090、当前3217的组合。查询并非同一时刻，原因未确定，不能据这些读数推断稳定频率、具体故障或此前卡顿原因。原始遥测、补充查询及命令均保留在 `timing/telemetry_audit_addendum.json`，未改频率、未据此删点或重跑计时。

墙钟与 CUDA 事件区间数据原样保留；CUDA 区间包含主机提交／同步造成的设备等待，不能等同于纯 kernel 忙碌时间。当前仅一台设备、两个模型、四个依赖视角，无锁频、独立场景总体置信区间或像素层面的统计显著性主张。

## 下一步优先级

先为完整参考与局部方法同时增加可共享的基线／GT 矩缓存，保留高精度分数核验，再做同精度、同输入合同的完整成本对照。当前很高的原型比值不能替代这个更强的基线。

然后再处理动态布局 CPU 同步及缓存内存开销，并在冻结的多视角／独立场景候选上评估收益聚合。单视角 PNG8 SSE 的目标／视角不一致问题在本轮没有消失；改变评分实现不会自动带来密度策略、几何质量或最终图像质量提升。现有证据尚不足以宣称学术创新或完成科研总目标。
