# v10：单遍精确回退通过两个新场景的精度及算子成本验证

本轮范围仍是数学核验和固定输入 CUDA 诊断，没有优化器、完整训练、GT 质量评估或参数搜索。
结果支持一个可复现的工程结论：v9 单遍 coarse 在新增室内外检查点上保留指定 native64 前向输出，并减少该参考实现的算子耗时。
这尚未完成“有学术价值的方法/数学贡献及质量、效率验证”的总体目标。

## 输入与选择规则

模型来自 [TGS 官方仓库公开的预训练模型入口](https://github.com/trianglesplatting/triangle-splatting#trained-models-and-rendered-test-views-on-mipnerf360)。
沿用原 ZIP listing，在观察新模型输出前按最小压缩体积分别选择一个新室外、一个室内 iteration7000 检查点；排除旧 stump，固定同训练步数，不能因 room30000 较小就替换。

- flowers7000：938,101 个三角形，SH3，实际分辨率 1256×828，sigma 范围约 0.1511–4.3116。
- room7000：2,100,000 个三角形，SH3，实际分辨率 1557×1038，sigma 范围约 0.1865–7.0764。
- 每场景在输出前按固定 SHA 规则选一个 test、一个 train 相机：flowers `_DSC9128` / `_DSC9169`；room `DSCF4915` / `DSCF4697`。
- 四图每版本总计 5,312,268 个像素。它们是两个按传输体积有目的选取的场景，不是随机场景、独立训练种子或数百万个独立科学样本。

仅从公开 archive 以 HTTP Range 提取十个成员，CRC/SHA 校验完成；两次尝试累计成功载荷 608,581,345 B，低于 650 MiB 上限。没有整包下载或上传本地研究数据。
初次在最后一个 room PNG 请求发生实际 RemoteDisconnected，进程 exit1；保留失败后原脚本校验并跳过九个完整成员，只补取缺失 PNG，exit0。
checkpoint 用 weights_only 安全加载及既有窄 NumPy 白名单读取；没有执行下载的模型代码。真实训练 commit 和历史训练 mask 仍未证明。

分辨率检查发现 flowers 的 5025/4 不能强取 ceil=1257，公开 PNG 实际宽1256。官方 loadCam 使用解码图像尺寸，FoV 仍由 COLMAP 尺寸与焦距决定。
该输入假设在渲染前修正，未修改相机选择、精度阈值或已有 v9 结果。PNG 仅作分辨率证据，未由其整数文件名猜测 GT 相机身份；其他训练图像字节没有逐张解码。详见 `TGS_CROSS_SCENE_INPUT_NOTE_V10.md`。

## 精度、缓存证书及审计修正

直接加载只读的 v9 coarse、旧 v5 oracle 及各自 counter twin，没有编译新候选，也没有继续测已失败的 standard。
四版本均执行四张完整图像和 RGB / weighted-depth 两种固定上游，每次反向的六组完整数组均保存为 NPY。
独立审计分块重新计算了全部梯度误差，没有用抽样梯度代替完整数组。

四相机的 RGB、全部七辅助通道、maxblend、半径、last/median 路径实际字节均等于指定 oracle。
所有 replay flags 和 preflight 计数为零；counter/lean 的前向、路径、系数及误差缓存也逐位一致。
coarse/oracle 六组完整 VJP 的最大相对差分别为：

- flowers test：8.05413e-7；flowers train：9.38086e-7。
- room test：8.02194e-7；room train：6.34625e-7。

各组有限，均满足原定相对1e-5（极小参考时绝对1e-6）的门槛；counter/lean VJP 也通过。
不要求原子加法梯度逐位可重复。既有 CPU 物理参照和 FD 证据被继承，没有重复计为新独立实验。

所有可见三角形-相机实例的缓存域和 footprint 均核验；每图预定544个三角形去重后的1632条边用 Fraction 检查，合计6528条。
这仍是对缓存 binary64 平面及指定运算的条件外部证书，不是对原始投影/几何的普遍证明，也不证明新颖性。

首版独立审计在 flowers train 失败。额外诊断对四图完整重捕获，定位为25,910个 radii0 不可见三角形的未初始化 anchor 字节；所有定义输出和可见缓存均一致。
源码在早退时不写 anchor，binning/backward 仅消费 radii>0；首版审计错误地要求不可见未定义 scratch 可复现。
保留原脚本、失败、部分 progress 和原数组，另版审计在全部相机上仅对 anchor/rect 使用源码定义的 radii>0 mask，其他输出及完整 VJP 继续全查，且加强为实际字节比较。
半径自身先在全部行逐位检查，mask 不能隐藏可见性差异。新审计源码和原失败/诊断哈希在重跑前单独冻结，所有四图最终通过。
这项修正没有改变 GPU 实现、队列、相机或浮点阈值。详见 `TGS_CROSS_SCENE_AUDIT_REPAIR_V10.md`。

另外，普通 np.array_equal 合并正负零，不能单独作为字面“逐位”证明。本轮补充真实字节核验：旧 v9 共2948字段、新 v10共88字段，以及旧2592对FD正负端点样本，均零差异。
补充审计写入新目录，旧封存数据不变。这不等于所有有限差分数值误差都小于1e-3。

## 成本：新场景有收益，但仍有较大的历史实现差距

在完整精度审计通过后，按预先冻结的方案执行：flowers阶段、room阶段；每相机六个排列各三次，72平衡block、216正式前向＋反向调用，另36固定预热。
同一时刻仅该场景模型常驻，模型、上游及相机张量的前后哈希一致；所有原始调用均保留，没有因时钟、离群或正负结果重跑。

主估计量是同 block coarse/oracle 墙钟前后向比值的中位数，按相机分别报告；不是边际时间中位数之比。
配对20,000次重采样的描述性95%百分位范围和主比值为：

- flowers test：0.732411，[0.685597, 0.764976]，耗时减少26.76%。
- flowers train：0.754310，[0.721038, 0.784720]，耗时减少24.57%。
- room test：0.803530，[0.762734, 0.853234]，耗时减少19.65%。
- room train：0.783554，[0.740696, 0.834179]，耗时减少21.64%。

独立成本审计重新构造了全部顺序、配对估计和重采样结果。四相机均通过事先固定的中位数<=.90且描述性上端<1的工程筛选。
这支持收益在本轮两个新场景中出现，不能由此推断所有场景或完整训练的总体加速。

前向配对中位比约0.732–0.783，反向约0.742–0.824。诊断工作量中，进入精确窗口的比例为 flowers14.73% /15.56%，room20.77% /16.77%。
room部分场景收益较小与工作分布不同相容，但未进行排除其他成本来源的因果分解；不能仅由计数断言性能瓶颈。

历史 piecewise 是不同数值语义的背景比较：coarse/piecewise 的配对中位比为5.008 /4.812 /3.876 /4.673。
因此此次依然没有达到该历史实现的速度，也没有证明两者实际 GT 图像/几何质量相当。
相对 oracle 的 Torch allocated 峰值，flowers每图增加15,009,792 B，room每图增加33,600,000 B；这不是显存优化。
所有allocated/reserved/incremental数值都保留在分析中，不等同driver、局部存储或完整训练峰值。

GPU为RTX5090 Laptop、CUDA12.8。72个block前后边界采样中，graphics clock为1567–2970MHz、温度51–60°C；初始未装入场景的空闲快照22MHz另行保留。
这些是边界遥测，不是调用内连续时钟追踪。两个场景是同一次未锁频会话的两个阶段，block可能时间相关。
区间仅描述本会话的配对分布，不是跨场景/训练种子的总体置信区间，不报告p值。
计时包含native API分配、.item主机同步和launch gaps，不是纯kernel或完整训练吞吐。

科研图 `cost/paired_cost.png/.pdf` 保留全部主比较原始点及不同数值历史背景，图源CSV和脚本一并保存，已视觉核查标签、范围、图例无裁切。
分析首次提交被自动审批额度通道拒绝，实际未执行；实时额度工具之后显示允许使用，沿同一审批路径一次重试获准。没有更换执行通道或重跑GPU实验，最终分析/审计/绘图均exit0。

## 对总体目标的意义及下一步

现已在旧stump及新flowers/room上形成可复现的参考等价与算子成本证据。应把它保留为精度/效率基线，避免仅在旧相机上继续修补极少数像素。

下一优先级是验证GT相机身份与实际图像/几何价值：用原始图像像素匹配加源码顺序证明建立对应关系，再提前固定质量比较计划。
若相对历史piecewise的质量收益不足以抵偿数倍成本，应降低全精确窗口路线的优先级，转向有数据支持的几何或优化问题，同时保留这套基线作为诊断参照。
并行的研究问题是剩余预处理、精确内部窗口和反向的实际成本分解；先冻结可区分这些解释的诊断，不从外部窗口计数直接宣称原因。

任何近似内部alpha方案仍需处理完整合成的数值轨迹；v8与standard失败不能用局部14点回放或经验power网格抹除。
数学新颖性、实际质量及训练收益仍未成立，本轮不扩展到完整训练。原始源归档、v9封存证据和打开的median_depth_note.tex未修改。
