> 接手本项目，先恢复证据与环境状态，暂不训练或拟合。目标是基于 3DGS／GGGS／2DGS／Triangle Gaussian Splatting 获得有数学或实际质量／效率价值的成果；当前总目标没有完成，不能把数值验证成功写成新颖性或泛化成功。
>
> 当前最新封存阶段是 TGS v29；主策略在 flowers 和 room 的新留出均退化。v30 仅有后续设计，尚无实现和可执行协议。先逐项核对交接里的小回执与接收到的外部资产；依赖缺失时列明，不覆盖旧输出、不假造重现。
>
> 人类最后允许数学核验和小规模固定输入 CUDA 诊断，后又要求最小收尾。先提交接手状态和具体诊断计划。后续若继续，第一工作包是原生颜色响应系数及固定正负 DC 扰动验证；任何优化器步骤、拟合、完整训练或扩大预算先按新的明确人类授权执行。不要直接运行提案中的100步。
>
> 保持既有协议、原 checkpoint、原始结果、失败回执与 manifest 不变。新的实现／修复／迁移适配放在新的独立阶段目录，写明输入哈希、源码哈希、环境、随机种子、相机划分、预算、成功门槛与退出码。原封存路径已存在就停止，不复用覆盖；新增补充清楚连接旧失败。
>
> 区分实数公式／浮点实现／固定查询效率／完整训练质量／学术新颖性；所有未实现项明确标为提案。不要自动扩候选、步数、种子、λ或换测试视角追求好结果。完成一段有退出码和证据的工作就记录停止点，避免长工具等待后丢失状态。

## 首次接手的最小核验

1. 核对传输文件和 SHA256，确认拿到的是代码包还是完整外部资产；[copied_receipts.json](copied_receipts.json) 只覆盖精选小证据。原 manifest 有绝对路径，迁移后需要新路径映射记录。
2. 只做只读环境／进程核验，记录 GPU、驱动、Python、Torch、编译器以及 CUDA arch；查是否已有训练仍在运行。旧 NVIDIA 快照或旧终端句柄不证明当前状态。
3. 对照 [v29 结果](../unified_geometry_gs/research/TGS_JOINT_POLICY_RESULT_2026_10_21.md)、[研究定位修正](../unified_geometry_gs/research/TGS_RESEARCH_POSITION_UPDATE_V29.md) 与 [下一工作包](../unified_geometry_gs/research/TGS_BOUNDED_APPEARANCE_NEXT_PLAN_V29.md)。不要从早期 README 的“最新”开始盲跑。
4. 新一轮实现先形成短协议和固定输入。零偏移 native 对齐失败或有限扰动越界即保留失败停止，先定位颜色／裁剪／排序／事件契约，不先拟合。

## 原生契约与易踩问题

- 最近 replay 使用物理质心方向 Python SH，原模型外部 FP32 颜色固定、子项颜色单独算。改变整张量长度后重算全体 SH 会造成全局舍入差；不得混用契约。
- alpha cap 为 .99，cutoff 为 1/255；`T < 1e-4` 检查发生在纳入当前贡献之前。tie 顺序、完整 contributor 列表、全图损失归一化与 SSIM 邻域都属于协议。
- v21 原生控制封装只做前向，不能当作训练入口。历史工程曾完成完整训练，但接收环境是否能训练必须另外验证。
- C++ 扩展的张量整型接口使用适当的 `int64_t`；过去 `long long` 特化不匹配导致链接问题。NumPy 2.4 对 size1 转标量应显式 `.item()`。这些是历史排错线索，非已在新环境验证的结论。
- 旧终端或 WSL 返回超时不等于工作已停。先看原 PID／句柄／日志／退出码，避免启动相同输出目录的重复训练。诊断不要连带删除环境或重装驱动。
- 使用原论文核验先验工作；v26 的比较范围已被 v29 修正。当前总目标没有被论文或完整实证关闭。
